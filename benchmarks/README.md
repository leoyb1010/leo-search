# Leo Search 1.4.0 验收

本组基准固定了 20 个公开技术问题，包括英文/中文搜索、官方文档和正文读取。它是可重复的**检索契约测试**，检查非空正文、来源字段与主题相关词；不是答案语义准确率、完整引用支持率或全平台召回率测量。

2026-09-05 本机结果：

- `results/retrieval.json`：首轮 18/20；26 次网络请求（含发现与网络降级），16 次请求复用。
- `results/fallback.json`：只对两个失败项走已知官方页面的 Jina 路径，2/2 成功，4 次网络请求。首轮结果保留，不覆盖为全绿。
- 两轮合计 20/20 问题取得可用来源，共 30 次网络请求；这是一次发布验收，不是普通搜索的默认成本。
- `results/native-mcp.json`：原生宿主识别 Exa、Context7、TinyFish 工具；TinyFish OAuth 更新后完成 1 次实际 search，0 次模型调用。
- `results/doctor.json`：连接与资源检查；TinyFish OAuth 元数据为 INFO，检索状态不从这里推导。
- `results/smoke.json`、`jina-retry.json` 保存早期失败证据。之后修复了 Jina JSON/SSE 解析、缓存警告保留和仅识别真实来源字段的检查。

## 使用成本

`python3 scripts/smoke.py` 默认只跑三个探针，最多 8 次网络请求；只有发布/重大路由变化才执行全量基准。`--case` 只重测失败项；`--fallback-only` 直接走已知官方页面，避免反复撞失败服务。硬预算包括 tools/list、查询、读取和一次网络降级。相同请求在单个进程内合并复用，进程结束即清空。

测试不读取私有账号内容、不把凭据写入报告、不运行浏览器或模型推理。`codex_probe.py --search` 通过原生宿主管理的 OAuth 使用临时执行上下文，退出后销毁，不持久化任务。
